# Clearance

Done + evidence + human-accept desk for agent deliverables (PRs, reports, decks, sites).

## What is Clearance?

Clearance is a verification and acceptance system for work delivered by AI agents. It provides a structured way to:

1. **Verify** that deliverables are complete with cryptographic evidence
2. **Assess** completion with deterministic verdicts (DONE, NOT_DONE, NEEDS_HUMAN)
3. **Accept** (or reject) deliverables through human review

## Who Should Use This?

- Teams deploying AI agents that produce code, reports, or other artifacts
- Organizations requiring evidence-based verification of agent work
- Developers who need a lightweight approval desk for automated workflows

## Benefits

- **Cryptographic verification**: SHA-256 fingerprints prevent evidence tampering
- **Deterministic verdicts**: Clear, reproducible assessments of completion
- **Human-in-the-loop**: Final acceptance requires human judgment
- **Local-first**: No external dependencies or paid APIs
- **Audit trail**: Every packet captures the ask, evidence, verdict, and acceptance

## Why Not Drydock or Fleetcourt?

- **Not Drydock**: Clearance is not a MERGE/BLOCK ship gate for individual PRs. It's a broader deliverable verification system that can handle reports, sites, and any artifact with file-based evidence.

- **Not Fleetcourt**: Clearance doesn't mediate multi-agent disagreements. It verifies evidence and defers to humans for acceptance decisions.

- **Not Homefield**: No harness bake-off or agent comparison. Clearance accepts work from any source.

- **Not Redline**: No prompt/skill A/B testing. Clearance verifies what was delivered, not how it was produced.

## Usage

### CLI

Create a packet JSON file describing the work and evidence:

```json
{
  "id": "pkt_example_001",
  "ask": "Implement user authentication",
  "evidence": [
    {
      "type": "file",
      "path": "./src/auth.ts",
      "sha256": "abc123..."
    },
    {
      "type": "text",
      "content": "Tests passing: 42/42"
    }
  ],
  "createdAt": "2026-09-03T12:00:00.000Z",
  "humanReviewRequired": false
}
```

Verify the packet:

```bash
npx clearance verify packet.json
```

Accept, reject, or request changes:

```bash
npx clearance accept pkt_example_001
npx clearance reject pkt_example_001 "Incomplete implementation"
npx clearance request-changes pkt_example_001 "Add error handling"
```

### Web Desk

Start the web interface:

```bash
npm run web
```

Visit http://localhost:43126 to view and manage packets.

## Packet Schema

A **Clearance Packet** contains:

- `ask`: Description of the work requested
- `evidence`: Array of evidence items (files, text, URLs)
- `SHA-256 fingerprints`: Cryptographic verification of file evidence
- `verdict`: DONE | NOT_DONE | NEEDS_HUMAN (generated by verification)
- `acceptanceStatus`: pending | accepted | rejected | changes_requested (set by humans)

## Evidence Types

1. **File**: Reference to a local file with optional SHA-256 fingerprint
2. **Text**: Inline text content (e.g., test results, logs)
3. **URL**: Reference to external resources (not fetched or verified)

## Verdict Rules

See [docs/verdict-rules.md](docs/verdict-rules.md) for detailed logic.

- **DONE**: All evidence exists, all fingerprints match, no human review required
- **NOT_DONE**: Missing evidence or fingerprint mismatch
- **NEEDS_HUMAN**: Evidence valid but `humanReviewRequired: true`

## Limitations

This is an honest assessment of what Clearance does **not** do:

- **No automatic screenshot verification**: Screenshots can be evidence, but visual correctness must be verified by humans
- **No URL fetch or verification**: URLs are recorded but not validated
- **Local-only**: Designed for local filesystem evidence; no cloud storage integration
- **Human review is a schema flag**: The `humanReviewRequired` field is set in the packet, not derived from signatures or advanced heuristics
- **No agent orchestration**: Clearance verifies deliverables but doesn't schedule, coordinate, or communicate with agents

## Fixtures

Test fixtures demonstrating verdict differentiation:

- `fixtures/clear-done.json` → DONE verdict (all evidence valid, can accept)
- `fixtures/missing-evidence.json` → NOT_DONE verdict (files missing)
- `fixtures/needs-human.json` → NEEDS_HUMAN verdict (requires human review)
- `fixtures/tampered.json` → NOT_DONE verdict (fingerprint mismatch)

Run verification on fixtures:

```bash
npx clearance verify fixtures/clear-done.json
npx clearance verify fixtures/missing-evidence.json
npx clearance verify fixtures/needs-human.json
npx clearance verify fixtures/tampered.json
```
